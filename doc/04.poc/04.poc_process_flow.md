# ELVIS (Electric Vehicle Charging Infrastructure System) Platform PoC 법인 회원 충전 라이프사이클 프로세스 명세서 (PoC Reference Process Flow)

본 문서는 **ELVIS (Electric Vehicle Charging Infrastructure System) Platform PoC(Proof of Concept)** 사업 수검 및 검증을 위한 **단일 기준 프로세스인 법인 회원 RFID 카드 태깅 충전 라이프사이클 (`UserType.C`)**의 상세 연동 프로세스 명세서입니다.

---

## 1. 📌 PoC 프로세스 검증 개요

- **대상 시나리오**: **법인 회원 실물 RFID 카드 태깅 충전 (UserType.C)**
- **검증 목적**: 
  1. 2,000대 가상 충전기의 부팅(`BootNotification`)부터 법인 RFID 회원 인증(`Authorize`), 충전 시작(`StartTransaction`), 충전 종료(`StopTransaction`)까지 E2E 라이프사이클 정상 동작 검증
  2. Java 25 Virtual Threads 기반 Kafka 인바운드/아웃바운드 메시지 버퍼링 및 MySQL 9.71 OLTP / ClickHouse OLAP 이중 적재 안정성 검증
  3. 계절별/시간대별 단가(TOU) 계산을 통한 과금 CDR 원장 영속화 및 관제 UI(`elvis-control-ui`) 실시간 모니터링 연동 검증

---

## 2. 🔄 법인 회원 충전 E2E 시퀀스 다이어그램 (`UserType.C`)

```mermaid
sequenceDiagram
    autonumber
    actor 사용자 as 법인 사용자 (User)
    participant 충전기 as 가상 충전기 (Charger)
    participant GW as WS Gateway (ELVIS-CONNECT-WS)
    participant Broker as Kafka Broker
    participant Sync as Consumer Engine (ELVIS-CONNECT-SYNC)
    participant Redis as Redis Cache
    participant MySQL as MySQL DB (OLTP)
    participant CH as ClickHouse DB (OLAP)
    participant Admin as 관제 API & UI (ELVIS-CONTROL)

    %% ==========================================
    %% 1. 부팅 및 초기 설정 (BootNotification)
    %% ==========================================
    rect rgb(240, 248, 255)
        Note over 충전기, GW: Phase 1: 부팅 및 소켓 연결
        충전기 ->> GW: WebSocket Handshake & Auth (Basic Auth/Token)
        GW -->> 충전기: WS Connection Established
        충전기 ->> GW: BootNotification.req (model, vendor, serialNumber, firmwareVersion, iccid)
        GW ->> Broker: ocpp-raw-events Produce (BootNotification)
        Broker ->> Sync: Consume BootNotification
        Sync ->> MySQL: 충전기 마스터 검증 & Boot 이력 저장 (tb_boot_tr)
        GW -->> 충전기: BootNotification.conf (status = Accepted, currentTime, interval=10s)
    end

    %% ==========================================
    %% 2. 법인 회원 카드 인증 (Authorize)
    %% ==========================================
    rect rgb(245, 245, 220)
        Note over 사용자, GW: Phase 2: 법인 회원 RFID 카드 태그 인증
        사용자 ->> 충전기: 실물 법인 회원 카드 태그 (UserType.C, idTag)
        충전기 ->> GW: Authorize.req (idTag)
        GW ->> Broker: ocpp-raw-events Produce (Authorize)
        Broker ->> Sync: Consume Authorize
        Sync ->> Redis: csmsCertDao.findByIdtag(idTag) 조회
        Redis -->> Sync: CsmsCert (법인 유효성, 회원번호, 차량번호, 빌링키 상태)
        
        alt CsmsCert 존재 및 법인 회원 유효함
            Sync ->> Broker: ocpp-outbound-commands Produce (AuthorizeResponse: Accepted)
            Broker ->> GW: Consume Outbound Command
            GW -->> 충전기: Authorize.conf (status = Accepted)
            충전기 ->> 사용자: 인증 성공 알림 & 커넥터 연결 유도
        else 미인증 또는 법인 계약 만료
            GW -->> 충전기: Authorize.conf (status = Invalid)
            충전기 ->> 사용자: 인증 실패 알림
        end
    end

    %% ==========================================
    %% 3. 충전 시작 (StartTransaction)
    %% ==========================================
    rect rgb(230, 230, 250)
        Note over 충전기, Admin: Phase 3: 충전 시작 및 거래 세션 생성
        충전기 ->> GW: StartTransaction.req (idTag, connectorId, meterStart, timestamp)
        GW ->> Broker: ocpp-raw-events Produce (StartTransaction)
        Broker ->> Sync: Consume StartTransaction
        Sync ->> Redis: 회원/차량 정보 매핑 (parentIdTag = 차량번호, userNo = 회원번호)
        Sync ->> MySQL: 분산 거래 ID 채번 & tb_start_tr 저장
        Sync -->> GW: Outbound StartTransaction.conf (status = Accepted, transactionId)
        GW -->> 충전기: StartTransaction.conf (status = Accepted, transactionId)
        충전기 ->> 사용자: 커넥터 잠금 & 실시간 충전 개시

        %% 실시간 미터값 적재
        loop 매 1초/10초 주기로 전력량 전송
            충전기 ->> GW: MeterValues.req (transactionId, meterValue, sampledValue)
            GW ->> Broker: ocpp-raw-events Produce (MeterValues)
            Broker ->> Sync: Consume MeterValues
            Sync ->> CH: ClickHouse 시계열 Bulk Batch Insert (1초 전력량)
            Sync ->> Broker: ocpp-ui-notifications Produce (실시간 상태 반영)
            Broker ->> Admin: Consume UI Notification
            Admin -->> Admin: 웹관제 UI 실시간 차트 & GIS 핀 업데이트 Push
        end
    end

    %% ==========================================
    %% 4. 충전 종료 및 정산 (StopTransaction)
    %% ==========================================
    rect rgb(255, 240, 245)
        Note over 사용자, Admin: Phase 4: 충전 종료, TOU 요금 계산 & CDR 영속화
        사용자 ->> 충전기: 충전 중지 버튼 클릭 (또는 카드 재태그)
        충전기 ->> GW: StopTransaction.req (transactionId, idTag, meterStop, reason, transactionData)
        GW ->> Broker: ocpp-raw-events Produce (StopTransaction)
        Broker ->> Sync: Consume StopTransaction
        Sync ->> MySQL: tb_start_tr 시작전력량 조회
        Sync ->> Sync: 계절별/시간대별 요금 단가(TOU) 연산 & 사용 전력량 계산
        Sync ->> MySQL: oper_rechg_hist (운영 충전 이력) 및 과금 CDR 원장 영속화
        Sync ->> MySQL: tb_rechgr_status 충전기 상태를 Available로 Update
        GW -->> 충전기: StopTransaction.conf (status = Accepted)
        충전기 ->> 사용자: 충전 완료, 커넥터 잠금 해제 & 최종 결제/과금 안내
    end
```

## 3. 📝 PoC 단계별 상세 처리 규격

### 3.1. Phase 1: 부팅 및 소켓 연결 (`BootNotification`)
- **충전기 전송 패킷**: `BootNotification.req (chargePointModel, chargePointVendor, chargePointSerialNumber, firmwareVersion, iccid)`
- **게이트웨이(`ELVIS-CONNECT-WS`) 처리**:
  - Netty/Spring WebSocket `HandshakeInterceptor`에서 ChargeBoxId 및 Token 검증
  - 수신 패킷을 Kafka `ocpp-raw-events` 토픽으로 비동기 발행
- **Consumer(`ELVIS-CONNECT-SYNC`) 처리**:
  - 충전기 마스터 DB 조회를 통한 등록 충전기 여부 확정
  - `tb_boot_tr` 테이블에 부팅 이력 저장 후 게이트웨이를 통해 `BootNotification.conf (status = Accepted)` 응답

---

### 3.2. Phase 2: 법인 회원 RFID 카드 인증 (`Authorize`)
- **충전기 전송 패킷**: `Authorize.req (idTag)`
- **Consumer(`ELVIS-CONNECT-SYNC`) 처리**:
  - `CsmsCertDao.findByIdtag(idTag)`를 호출하여 Redis 캐시 및 MySQL 회원 마스터 조회
  - **법인 회원 유효성 검증 항목**:
    1. 법인 회원 등록 여부 (`UserType = 'C'`)
    2. 법인 계약 상태 (정상/정지)
    3. 법인 연동 빌링키 만료 여부
  - 검증 성공 시 `Authorize.conf (status = Accepted)`, 실패 시 `Invalid` 전송

---

### 3.3. Phase 3: 충전 시작 및 실시간 전력량 적재 (`StartTransaction` & `MeterValues`)
- **충전기 전송 패킷**: `StartTransaction.req (connectorId, idTag, meterStart, timestamp)`
- **Consumer(`ELVIS-CONNECT-SYNC`) 처리**:
  - `parentIdTag`에 차량번호(`userNm`), `userNo`에 회원번호 설정
  - MySQL 시퀀스/분산 매니저 기반 신규 `transactionId` 채번
  - `tb_start_tr` 테이블에 충전 시작 정보 저장
- **1초 미터값 적재 (`MeterValues`)**:
  - 충전 중 전송되는 `MeterValues.req` 패킷은 `ConcurrentLinkedQueue` 버퍼에 저장
  - 1초 단위로 ClickHouse OLAP DB에 **JDBC Batch Bulk Insert** 수행 (고성능 시계열 적재)
  - 관제 백엔드(`ELVIS-CONTROL-API`)로 Kafka 알림 이벤트를 발행하여 **Vue 3 관제 UI 화면에 실시간 차트 반영**

---

### 3.4. Phase 4: 충전 종료, TOU 정산 & 이관 (`StopTransaction`)
- **충전기 전송 패킷**: `StopTransaction.req (transactionId, idTag, meterStop, timestamp, reason, transactionData)`
- **Consumer(`ELVIS-CONNECT-SYNC`) 처리**:
  - `tb_start_tr` 테이블의 `meterStart`와 `StopTransaction.req`의 `meterStop` 차이로 총 사용 전력량($kWh$) 산출
  - 계절별(봄/여름/가을/겨울) 및 시간대별(경부하/중간부하/최대부하) **TOU 요금 단가표 연산 엔진** 호출
  - 계산된 최종 과금 금액 및 CDR 원장을 MySQL `oper_rechg_hist` 테이블에 영속화
  - 충전기 상태를 `Occupied` ➔ `Available`로 최신화하고 `StopTransaction.conf (status = Accepted)` 하향 전송
