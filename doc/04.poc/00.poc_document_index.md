## 2. 🏷️ 제품군 풀스펠링 및 모듈 명칭 규격 (Full Product Suite Specification)

모든 문서 및 소스 코드 패키지는 아래 정의된 **제품군 풀스펠링(Full Product Name)** 및 **표준 모듈 코드** 규격을 엄격히 준수합니다:

```text
ELVIS (Electric Vehicle Charging Infrastructure System) Platform Suite
 │
 ├── [제품군 1] ELVIS-CONNECT (Electric Vehicle Charging Connector & Data Pipeline Suite)
 │    │          : 충전기 단말 접속 수용 및 비동기 데이터 파이프라인 제품군
 │    ├── ELVIS-CONNECT-WS   (elvis-connect-ws)   : Netty/Spring WebSocket 기반 OCPP 게이트웨이 모듈
 │    └── ELVIS-CONNECT-SYNC (elvis-connect-sync) : Java 25 Virtual Threads 기반 Consumer & DB 이중 적재 모듈
 │
 ├── [제품군 2] ELVIS-CONTROL (Electric Vehicle Charging Station Control & Admin Portal Suite)
 │    │          : 전기차 충전소 실시간 관제 포털 및 어드민 백엔드 관리 제품군
 │    ├── ELVIS-CONTROL-API  (elvis-control-api)  : Spring Boot 관제 백엔드 REST API & WebSocket Push 모듈
 │    └── ELVIS-CONTROL-UI   (elvis-control-ui)   : Vue 3 / Vite SPA 기반 웹 관제 프론트엔드 모듈 (Nginx Reverse Proxy)
 │
 └── [공통 인프라] ELVIS-TESTER (Electric Vehicle Simulator & Offline Package Installer)
      │          : 2,000대 가상 충전기 부하 시뮬레이터 & 폐쇄망 단일 원클릭 무인 인스톨러 모듈
```

## 3. 🧩 WBS ID 명동 체계 및 코드 풀스펠링 해설 (WBS ID Full Code Structure)

WBS 일정표 및 세부 작업에서 사용되는 **`WBS ID` 코드 구조(`WBS-[제품군]-MODULE-[기능ID]-[공정단계]`)**의 약어 풀스펠링 해설은 다음과 같습니다:

```text
 예시: WBS-CONNECT-WS-101-A
  │    │       │  │   │
  │    │       │  │   └─ [공정단계코드] A: Analysis (요구사항 분석) / D: Design (설계) / C: Coding (개발)
  │    │       │  └───── [기능 세부 분류 코드] 101 ~ 111 (기반 구성, 연결 관리, 적재, 통계 등)
  │    │       └──────── [모듈 ID] WS: WebSocket Gateway / SYNC: Consumer Engine / API: Admin API / UI: Portal UI
  │    └──────────────── [제품군 풀스펠링] CONNECT (파이프라인 제품군) / CONTROL (관제 포털 제품군) / TESTER
  └───────────────────── [WBS 식별자] Work Breakdown Structure (작업 분할 구조)
```

| WBS ID 요소 | 구성 코드 | 풀스펠링 (Full English Name) | 한글 기능 풀이 설명 |
| :---: | :---: | :--- | :--- |
| **WBS 헤더** | `WBS` | **W**ork **B**reakdown **S**tructure | 작업 분할 구조 체계 코드 |
| **제품군 구분** | `CONNECT` | **C**ON**N**EC**T** Suite | 충전기 연결 및 데이터 파이프라인 제품군 (`ELVIS-CONNECT`) |
| | `CONTROL` | **C**ON**T**RO**L** Suite | 관제 포털 및 백엔드 어드민 제품군 (`ELVIS-CONTROL`) |
| | `TESTER` | **T**E**S****T**ER | 시뮬레이터, 패키징 및 통합 검증 서비스 (`ELVIS-TESTER`) |
| **모듈 ID** | `WS` | **W**eb**S**ocket Gateway | OCPP 1.6/2.0.1 웹소켓 게이트웨이 모듈 (`elvis-connect-ws`) |
| | `SYNC` | **Sync** Consumer Engine | 패킷 파싱, DB 이중 적재 및 이벤트 발행 모듈 (`elvis-connect-sync`) |
| | `API` | Admin Backend REST **API** | 관제 백엔드 REST API 및 WebSocket Push 모듈 (`elvis-control-api`) |
| | `UI` | Portal **U**ser **I**nterface | Vue 3 기반 웹 관제 프론트엔드 모듈 (`elvis-control-ui`) |
| | `SIM` | Charge Point **Sim**ulator | 2,000대 대량 전력 미터값 부하 시뮬레이터 모듈 |
| | `PKG` | Offline **Pkg** Installer | 폐쇄망 단일 원클릭 무인 자동 인스톨러 패키징 모듈 |
| | `TST` / `DEP` | **Test**ing / **Dep**loyment | E2E 통합 테스트 및 폐쇄망 Target VM 배포/이관 |
| **공정 단계** | `A` | **A**nalysis | 요구사항 정의 및 기능 분석 공정 |
| | `D` | **D**esign | 아키텍처, ERD, DTO 및 와이어프레임 설계 공정 |
| | `C` | **C**oding & Development | 소스 코드 구현, DB 적재/트랜잭션 개발 및 튜닝 공정 |

## 5. 📖 PoC 주요 약어 풀이표 (Acronym Definitions)

| 약어 (Acronym) | 정식 영어 표현 (Full English Name) | 한글 뜻 및 역할 설명 |
| :---: | :--- | :--- |
| **`ELVIS`** | **E**lectric **L**ink **V**erification & **I**nfrastructure **S**ystem | 전기차 충전 및 인프라 통합 검증 플랫폼 |
| **`PoC`** | **P**roof **o**f **C**oncept | 기술 검증 / 개념 증명 프로젝트 |
| **`CPO`** | **C**harge **P**oint **O**perator | 충전 사업자 / 충전 인프라 운영사 |
| **`CSMS`** | **C**harging **S**tation **M**anagement **S**ystem | 충전소 관제 및 통합 관리 시스템 |
| **`OCPP`** | **O**pen **C**harge **P**oint **P**rotocol | 개방형 충전기 통신 표준 프로토콜 (1.6 / 2.0.1) |
| **`WBS`** | **W**ork **B**reakdown **S**tructure | 작업 분할 구조 / 공정 단계별 상세 개발 계획표 |
| **`TOU`** | **T**ime-**O**f-**U**se | 계절별 / 시간대별 차등 요금 단가 체계 |
| **`CDR`** | **C**harge **D**etail **R**ecord | 충전 세션 상세 과금 원장 이력 데이터 |
| **`OLTP`** | **O**nline **T**ransaction **P**rocessing | 온라인 실시간 트랜잭션 처리 (MySQL DB 역할) |
| **`OLAP`** | **O**nline **A**nalytical **P**rocessing | 온라인 실시간 분석/집계 처리 (ClickHouse DB 역할) |
| **`CQRS`** | **C**ommand **Q**uery **R**esponsibility **S**egregation | 명령(쓰기)과 조회(읽기)의 역량 분리 아키텍처 |
| **`DLT`** | **D**ead **L**etter **T**opic | 처리 실패 메시지 격리 및 재처리를 위한 토픽 |
| **`WS`** | **W**eb**S**ocket | 실시간 양방향 소켓 통신 프로토콜 |
| **`E2E`** | **E**nd-**t**o-**E**nd | 단말부터 관제 화면까지의 전체 구간 통합 검증 |
| **`GIS`** | **G**eographic **I**nformation **S**ystem | 지리 정보 시스템 / 지도 기반 시각화 맵 |
| **`TPS`** | **T**ransactions **P**er **S**econd | 초당 처리 트랜잭션/패킷 건수 (성능 지표) |
| **`M/D`** | **M**an-**D**ays | 1인 기준 하루 투입 공수 (투입 인력 단위) |
| **`VM`** | **V**irtual **M**achine | 가상 머신 / 폐쇄망 격리 배포 타깃 환경 |
| **`SPA`** | **S**ingle **P**age **A**pplication | 단일 페이지 웹 애플리케이션 (Vue 3 기술 스택) |
